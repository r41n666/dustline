游戏：`D:/Dustline/dustline`，Unity **6000.3.23f1** Mono 发布版（无源码，`Dustline.exe` 667KB + `Dustline_Data` 700MB）。

### 关键结论（后续开发直接用）
- **Tuanjie/Unity 2022.3.62t16 编辑器对本项目无用**：游戏是 Unity 6000.3，2022.3 打包的 AssetBundle 无法加载。
  资源注入只能走**运行时解析**（本项目的 GLB 解析器即为此设计，与引擎版本无关）。
- **BepInEx 5.4.23.2 可在 Unity 6 Mono 上正常工作**（已实测注入 + 加载插件 + 应用 Harmony 补丁）。
- 游戏用**自研骨骼动画系统** `SourceRig`（直接驱动 Transform，非 Unity Animator），
  原版身体模型 `t_leet`(T) / `ct_idf`(CT) 在 `SceneView.CreateActor(id, team)` 里创建。
- 骨骼命名是 CS:GO 原生规范：`pelvis / spine_0..3 / neck_0 / head_0 / clavicle_L / arm_upper_L /
  arm_lower_L / hand_L / leg_upper_L / leg_lower_L / ankle_L / ball_L`（T方85 骨、CT方 94 骨）。
- 第一人称下 `SceneView.UpdatePlayers` 会把本地 actor `SetActive(false)` 且不驱动姿态 → 第三人称必须补回。
- `SourceRig.IsVisible` 为 false 时姿态被节流到 10Hz（`SourceCharacter.Pose`）→ 换皮后必须 patch 放行，
  否则所有玩家模型变 10 帧动画。
- 所有音效播放必经 `GameAudio.Clip(path)` → 受击音效在此前置拦截即可全局替换。
- 受击事件名：`Flesh.BulletImpact` / `Dustline.KevlarHit` / `Dustline.Headshot` / `Dustline.HelmetHit`
  / `Weapon_Knife.Hit` / `Weapon_Knife.Stab`（刀打墙 `Weapon_Knife.HitWall` 不换）。

### 踩过的坑
- glTF accessor 的 `byteStride` 要用**字节宽度**算：`componentByteSize(componentType) * components`。
  误用类型码（5126）会让步长变成 15378 字节/顶点，模型只剩 2618 面（应为 43176）。
- Sketchfab 导出的 GLB 关节名带 `_序号` 后缀（`upper_arm.L_68`），骨骼匹配需先归一化。
- glTF→Unity 坐标：顶点 Z 取反、四元数 `(x,y,z,w)→(-x,-y,z,w)`、三角形绕序反转、容器再绕 Y 转 180°。
- `miku.glb` 顶点原点在包围盒角上且尺寸巨大（14×7×19.5 单位），必须自动定标+居中（已实现 StaticHeight）。
- 游戏进程会随启动它的 shell 会话结束而被回收，测试需用长驻后台任务保持。
- 用 PowerShell `Start-Process` 启动会导致游戏提前退出，改用 bash 直接启动。

## 第三轮：T-pose / V 键 / 控制台的真实根因（重要教训）
**用户实机反馈**：姿态永远 T-pose、按 V 只有提示没换视角、高度不对、朝向反了、控制台不能发送/退出。

1. **T-pose 与骨骼映射无关**：日志实证 `mikuArmLocalEuler == gameArmLocalEuler`（本地与远端都成立），
   映射链路是对的。视觉 T-pose 来自**我自己设计的 WorldPose 手部钉位**：
   Q 版初音手臂比原角色长约 30%，手被钉死在原角色手位后只能伸直。
   → 修复：`hand_L/R` 改为 RotationOnly（骨盆与脚仍用世界位置，保证贴地/蹲伏/尸体物理）。
2. **身高对齐算法错了两次**：
   - 第一次用「头关节高度」对齐 → 初音 Q 版头大身短，四肢被拉长近 1 倍（scale 2.08）→ 更糟。
   - 第二次用 `Renderer.bounds` 测量 → 蒙皮更新前是**过期值**，模型只有 1.01m（明显偏小）。
   - 正确做法：`MeshFilter.sharedMesh.bounds` / `SkinnedMeshRenderer.sharedMesh.bounds`（bind pose AABB）
     ÷ 容器缩放 = 模型空间高度，再与角色 `head_0.y - ball_L.y` 比。实测 1.53m → 系数 1.07 → 总 scale 1.39。
3. **朝向**：`YawOffset` 应为 **180**（此前误设为 0，用户实机确认反了）。
4. **V 键**：原 `Evaluate()` 要求 `Local.Alive && Viewing == Local`，死亡/观战时永不生效，
   而提示 Toast 不管这些条件照常显示 → 用户看到"有提示但没反应"。已放宽为只看开关+相机+Playing+未开镜。
5. **IMGUI 控制台按键**：文本框获得焦点后按键会被 GUI 先行消费，
   `Input.GetKeyDown` 收不到 → 必须在 `OnGUI` 里用 `Event.current` 兜底处理回车/ESC/反引号。
6. **调试教训（反复踩）**：本机 PrintWindow 抓到的游戏窗口图与实际渲染内容不对应（System.Drawing 读全黑），
   小图也会误导朝向判断 —— **Unity Mod 的渲染问题必须以数值日志为准，不要以截图为准**。

## 第四轮（决定性根因）：蒙皮权重全为 0 —— 模型从不跟随骨骼
**用户反馈**："模型还是默认姿势，没有动作，高度更矮，枪不在手上，受击面积对不上，只有朝向对了"。

**根因**：`Gltf.ReadJoints()` 用 `(int)ReadFloat(...)` 读 `JOINTS_0`。
关节索引是**整数分量**（5121 unsigned byte / 5123 unsigned short），
而 `ReadFloat` 会做归一化 `3/255 = 0.0117` → 再 `(int)` 截断成 **0**。
⇒ 所有顶点的 boneIndex 全是 0、权重全 0 ⇒ **网格完全不蒙皮**，永远显示 GLB 绑定姿势（"默认姿势、没有动作"）。
连带的：枪不在手上（手部不跟随）、看起来更矮、误判为 T-pose。

**修复**：新增 `ReadIndex(ReadOnlySpan<byte>, int, int componentType)` 按整数类型直读，
`ReadJoints` 改用它。教训：**glTF 里"索引类"accessor 绝不能走浮点归一化路径**。

**方法论教训（本项目最贵的一条）**：
"骨骼角度日志一致" ≠ "模型在动"。必须区分 **骨骼 Transform 是否被写** 与 **蒙皮是否生效**。
验证蒙皮是否生效的正确方法：统计 `mesh.boneWeights` 中权重和 > 0 的顶点数（应为总顶点数），
而不是看骨骼 euler 或截图。

## 第五轮：模型炸开（蒙皮已生效但 bindpose 不一致）
用户截图：模型变成一团乱麻。**这说明蒙皮已经生效**（第四轮修好了权重），但坐标系/bindpose 不自洽。

连续两个结构性 bug（都在把 glTF 转 Unity 时）：
1. **只转了网格顶点、没转骨架节点**：顶点做了 Z 取反，但节点的 translation/rotation 原样使用
   ⇒ 网格与骨架不在同一空间。修复：新增 `ConvertPosition/ConvertRotation/ConvertMatrix`（M' = F·M·F，F=diag(1,1,-1)），
   节点层级与世界矩阵计算全部走同一套转换。
2. **bindpose 少了一项**：正确公式是
   `bindpose = inverse(boneWorldBind) * meshNodeWorldBind`
   （把「网格所在节点空间」映射到「骨骼空间」）。我原来只用了 `inverse(boneWorldBind)`，
   网格节点带位移时整体扭曲。已修。

⚠️ 教训：glTF→Unity 的**顶点、节点位移、节点旋转、节点矩阵、bindpose 必须用同一套坐标转换**，
少任何一处都会表现为"模型炸开"，而不是明显的报错。

## 第六轮：自检日志上线 + 坐标转换方向纠错
**自检日志已加入**（MikuModelFactory 构建结束时输出，`BepInEx/LogOutput.log`搜 `[selfcheck]`）：
```
[selfcheck] verts=36584 weighted=36584 bindposeDetMin=1.0000 bones=111
```
含义：顶点数 / 有效蒙皮顶点数 / bindpose 最小行列式 / 骨骼数。
判读：weighted 必须等于 verts；bindposeDetMin 应为 +1（负数=镜像错误）；bones 应与模型骨骼数一致。
**以后任何"模型变形/炸开"问题先看这行，不要先看截图。**

**坐标转换方向纠错**：我曾误信"模型是 Z-up"，加绕 X 轴 -90° 旋转 —— 自检日志立刻显示模型高度从
1.532m 掉到 0.455m，证明该模型本来就是 **Y-up**（Z-up 的是 armature，不是模型）。已回退为 Z 轴镜像。
教训：**"某资产是 Z-up"这类记忆要靠自检数字复核**，别直接照做。

**剩余形变来源（待验证）**：运行时骨骼镜像里，骨盆/脚踝/脚掌仍是 WorldPose（钉世界坐标）。
Q 版初音腿长比原角色长约 30%，脚被钉住会把小腿拉成长细条、骨盆钉位导致上半身前倾（鞠躬态）。
已把四根脚骨改为 RotationOnly（只保留骨盆 WorldPose）并部署，待实机确认。

## 第七轮：重定向逐项修到只剩"整体倾倒"，最后补根骨偏移
进展：模型已完全成型（四肢比例正常、姿势连贯、不再炸开/拉细/蜷缩），
只剩"整体向一侧倒"——根因是骨盆（pelvis）是 WorldPose 模式，旋转复制时**漏加 RestOffset**，
其他 20 根骨都带偏移、唯独根骨没有 → 整体绕骨盆转了一个静置差。已补：
`SetPositionAndRotation(game.position, game.rotation * RestOffset)`。

**重定向正确公式（完整版，已定稿）**：
- RotationOnly 骨：`mikuWorld = gameWorld * RestOffset`，`RestOffset = inverse(gameRestWorld) * mikuRestWorld`（bind 时刻标定）
- WorldPose 骨（骨盆）：位置 = game 位置，旋转同样要 `* RestOffset`（不能漏！）

**这是本项目最核心的一条经验**：无源码 Unity 游戏换皮，重定向 = 保留原骨架跑动画 + 逐骨「世界旋转 × 静置偏移」。
偏移必须在 bind pose 时刻标定一次，且**根骨也不能例外**。

## 第八轮：标定时机 —— bind pose 是「躺姿」导致整体倾倒
用户截图：模型成型、姿势连贯，但整体躺倒。**根因**：这套 Source 骨架的 bind pose 本身是「躺姿」
（Source 静置参考姿态），而我此前在 Initialize（bind 时刻）标定 RestOffset ——
等于把「躺姿→躺姿」的变换记成基准，游戏动画一旦站起来，初音就被反向转倒。

**定稿做法**：RestOffset 标定推迟到**第一帧姿态同步后**（LateUpdate 里，骨骼还没被写过之前）：
那一刻游戏骨架是站姿、初音是自己绑定姿势，offset = inverse(gameStanding) * mikuBind 才是正确的基准。
此后游戏动多少、初音跟多少。

⚠️ C# 坑：`foreach` 迭代变量不能改成员，标定循环要用 `for + pairs[i].RestOffset = ...`。
